## 前提

- kgchaos1.eu.cc 的 A 记录指向 8.133.220.164。
- 云安全组允许 80/443；80 仅用于证书验证和 HTTPS 跳转。
- 取得可信 TLS 证书，fullchain.pem 和 privkey.pem 放入 certificates/；私钥仅服务器保存且限制权限。必须配置自动续期并在续期后重载 nginx。
- 检查 Docker 172.29.91.0/24 未被其他网络占用，若冲突同时调整 compose 中两个IP与可信代理。
- 配置 PKM_PASSWORD_HASH（PBKDF2，不是明文密码）、随机 SECRET_KEY、PKM_PUBLIC_ORIGIN=https://kgchaos1.eu.cc。
- 备份 SQLite 必须使用在线 backup API 或停服务备份，不直接复制正在写入的数据库。

## 部署原则

使用独立 compose.secure.yml，避免隐式加载旧 override；保留原数据库/data及/backups挂载。先验证镜像、Python模块与认证测试，再切换。新源码只读挂载，后端不映射宿主机端口。仅操作 PKM 服务，不重启 Docker daemon，不停止其它项目。

不要在 DNS/证书未就绪时部署依赖证书的 nginx 配置，也不要允许不可信证书跳过验证传真实凭证。

## 验收

1. 公网 HTTPS 验证完整证书链和域名。
2. 未登录 /api/notes/ 与 /api/sources/ 及 /docs 返回401，health仅返回status。
3. Cookie Secure、HttpOnly、SameSite=Strict；跨站写请求被403拒绝。
4. 登录后保存收藏夹链接并同步，无需用户ID或传Cookie。
5. 任务展示真实计数及 partial/failed，不将0条占位视为成功。
6. 重启容器后笔记、数据源仍保留，密码配置仍有效。
7. 旧8090公网上不可直连；旧8091静态服务移除或仅跳转到HTTPS。
